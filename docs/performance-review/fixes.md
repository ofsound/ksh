# High-priority performance fixes — 2026-10-13

All three P1 findings from the performance review are fixed.

## Deferred MIDI timing

Pending notes store absolute sample deadlines on a monotonic callback timeline. Queues compare their deadlines with the current block start rather than decrementing offsets during different drain phases. Note-ons, note-offs generated by deferred note-ons, and audition note-offs keep the correct timing across fixed or changing block sizes. Pattern-switch cancellation compares against that same timeline. Reset clears both deadlines and the timeline.

The original probe now produces exactly `on=0 off=2688 on=3000 off=5688` at 48 kHz for every tested buffer size: 64, 128, 512, and 1024 samples. The former one-buffer delay is gone.

## Realtime-safe UI delivery

`processBlock()` only enqueues hits and sets atomic work flags; it no longer calls `triggerAsyncUpdate()`. The processor's existing 120 Hz message-thread timer delivers notifications and handles generation/recording with the editor closed. Before repainting, the visible 60 Hz editor also drains hit notifications so two separate timer phases do not introduce an extra frame of delay. Message-thread async updates remain available for UI commands and deferred generation.

A regression test verifies a hit-bearing audio callback does not leave an async update pending and that the processor timer delivers the hit exactly once. Visual presentation remains frame-based; timestamp-aligned display rendering was outside these three fixes.

## Latest snapshot delivery

The mailbox uses one lock-free atomic pointer for the pending update instead of a queue that can fill. Publishing replaces and recycles any unconsumed pending update, preserving the consumer's held snapshot. The audio thread swaps pointers and retires old slots without copying or destroying snapshots. Producer retirement is serialized with host engine changes under `engineStateMutex`.

A burst of publications 1 through 10 now delivers 10 on the next consumption without a retry or further edit. Tests also cover an immutable held snapshot during 10,000 publications, repeated consumption, 100,000 concurrent publications with payload integrity, and the final MIDI pitch after a processor edit burst during suspended processing.
