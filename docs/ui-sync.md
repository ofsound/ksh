# Native editor and engine contract

The C++ engine is authoritative. `PluginProcessor::nativeUiState()` copies an immutable playback snapshot, refresh length, revision and document epoch under the engine mutex. No painting calls the engine or builds JSON.

`KshUiBridge` is a message-thread notification boundary. Engine callbacks increment its revision; they never call an editor while the engine mutex is held. The processor alone drains the audio hit FIFO and delivers typed `NativeHit` notifications. The native controller registers for its lifetime and removes its callback on destruction. Audio processing remains snapshot-only and lock-free.

The visible editor polls at 60 Hz. Only changed state or flash/playhead regions repaint. Pending cell edits carry their original expected values and document epoch. `applyNativeCellEdits` validates the entire batch before applying it and publishes one coherent snapshot. Recording wins conflicts; replacement documents cancel drafts and clear history.

The audio callback only enqueues hit notifications and sets work flags. The processor drains them on its 120 Hz message-thread timer, including with the editor closed. The visible editor also asks the processor to drain hits immediately before its playback repaint pass. Audio processing never calls `triggerAsyncUpdate()` to wake the UI.

Pattern recording uses separate bounded queues for incoming MIDI (audio-thread producer) and pad/QWERTY input (message-thread producer). The message thread drains both queues under the engine mutex; no SPSC queue has multiple producers.

`RealtimeMailbox` coalesces unconsumed updates through one lock-free atomic pointer. A new publication replaces and recycles the previous pending snapshot, while the consumer's current snapshot remains immutable. Retired slots are recycled on the producer side; all producer operations are serialized by the engine mutex. Bursts while audio processing is suspended still deliver the latest state on the next callback.

Deferred MIDI note-ons and note-offs use absolute deadlines on a monotonic callback sample timeline. Block sizes can change without shifting an event's deadline. Playback reset clears the pending events and sample timeline together.

Cells carry an integer `nudge` from -100 to +100 percent of one step (zero is on the beat). It shifts the entire hit, including its roll repeats, before/after the normal swing and humanize timing. When early cells exist, the runner evaluates one step ahead and queues later hits on the same absolute sample timeline; the visible playhead still follows the host. Host loop-start hits are anticipated before the wrap. Starting playback or seeking cannot emit into the past, so an early hit at the landing step is clamped to the first sample. Stop and seek cancellation also discard anticipated notes.

The inspector's Nudge control replaces the selected-cell count. It applies a common delta to all enabled selected cells, anchored to the first selected cell's displayed percentage. Mixed values show a dash. The delta stops when any selected cell reaches -100% or +100%, preserving the group's timing differences. A gesture is one undo action; cancel and conditional history include the nudge field. Grid slots stay on the beat while enabled shapes, their selection outlines, accessible bounds and hit tests move horizontally by `nudge / 100 * cellWidth` in both layouts and layers.

The grid always includes deterministic swing in those positions, using playback's shared `swingDelayStepsForPosition` calculation. The filled cell starts at its first swung hit plus nudge; roll shading and onset ticks use each repeat's own calculated swing phase, including ticks beyond the cell body. Straight beat slots stay fixed. Swing/subdivision automation updates both paint and accessible bounds immediately. For channel loops and reverse/ping-pong modes, the display uses the cell's next visit in the playback order, refreshing its phase from an audio-thread atomic global-step counter. When stopped it previews the first visit. No timing values are written back to cells, and random humanize is not baked into this deterministic display.

Nudge persists in strict `v:1` projects through optional sparse `cellNudges` rows `[source, channel, step, percent]`, including disabled and hidden cells. The existing `cells` rows keep their nine-field layout, so historical ten-field cycle-offset rows remain unambiguous. Missing nudge data defaults to zero. Typed snapshots, copy/move, generated cells and JSON cell inspection all retain the field.

Transport discontinuities never leave notes hanging. Stop, device off, seeks, bypass and state restores send note-offs for every sounding note at sample 0 and drop queued note-ons. After a jump, a step whose start falls at the landing position plays; a mid-step landing waits for the next boundary. When the host reports a loop, steps at or after the loop end are left for the next pass. A wrap to the loop start keeps pending notes and cycle phases, and plays the loop-start step even if the host did not split the block there. Cycle phases restart per cell, only when that cell's cycle length or mask changes.

Generative modes pick sources on the audio thread at each refresh boundary with a fixed-seed RNG, so the step that opens a window plays the new choice and offline renders repeat. The runner reports its choices through a FIFO; the engine mirrors them for the preview only when they extend its current `generationVersion`. Deliberate recompositions (mode, lock or channel changes, reset) bump that version, and the runner adopts the engine's choices. Undo and redo keep the current generated sources rather than re-rolling them.

Discrete commands go directly to `dispatchUiEngineCommand`, without JavaScript or serialized command messages. Convert native zero-based indices to the engine's one-based command indices once at this boundary. Numeric APVTS gestures pair begin/end callbacks. Row audition calls `triggerRowFromUi` directly through the existing realtime queue.

History groups a gesture into one action and conditionally merges only its changed fields. External changes are rebased out of active transactions; undo/cancel preserve unrelated recording and automation. Histories are capped at 128 entries. History stores typed document settings plus only the cells a gesture changed; JSON is used only to apply an undo through the persistence validator. A scroll-wheel adjustment is one action and one host gesture, closed after 350 ms without ticks or as soon as another edit begins. Text fields retain their native text undo. Project loads use the existing strict v:1 persistence validator and atomic file replacement.

`KshLayout` supplies cell bounds and hit tests. The grid and generated preview remain together in one native editor. Overall scale is stored in project/host metadata at 50–120%. Imported theme metadata remains readable; all rendering uses the fixed Alternative palette and newly saved projects use `alt`.

iOS standalone uses automatic viewport fitting instead of the saved zoom. Landscape viewports up to 1100 × 500 points use a compact layout with eight channel rows, manual 16-step pages, an always-visible inspector and auxiliary control pages; see [iphone-release.md](iphone-release.md). Compact geometry and gesture modes are editor-local and never persisted. Wide viewports retain the original layout. The fullscreen wrapper owns editor bounds, with no fixed aspect ratio or minimum zoom constraint. The selected native layout is scaled uniformly and centred inside the available safe area on every resize or preferred-layout change. The scale control displays a read-only `Fit`; fitting does not overwrite project zoom metadata. Desktop standalone and hosted plugins retain their adjustable scale.

The desktop footer displays control help directly from each hovered control's `TooltipClient`, walking up from nested children when necessary. It replaces the old source/channel status line, is blank off controls, and wraps long tips across two lines without shrinking the font. There is no floating tooltip window. The footer `Tips` toggle beside `DC` enables this help and defaults on, independently of the retired floating-tooltip preference. Its `footerTooltips` preference is saved locally (`ofsound/KSH.ui.settings` in Application Support on Apple platforms), independently of project and host state. Compact layouts retain their existing geometry and tooltip strings.

The row-order icon between `Tips` and `DC` reverses vertical channel presentation: channel 1/red moves to the bottom and channel 8 to the top. `Layout` maps visual rows to the original channel indices for painting, hit tests, row controls, loop handles, keyboard navigation and drag targets. Generated previews follow the same order. The `reverseRows` preference is saved in the same local UI settings file; it never changes MIDI, cell data, project/host state, selection identity or undo history. Compact grids respect the preference while keeping their existing footer-free layout.

Select beside Velocity/Chance is an editor-local Shift modifier. Tap to latch or unlatch; holding for at least 300 ms, or using it for a modified action with another touch, is momentary. Physical Shift also lights Select, and releasing it preserves any latch. While active, cells retain the previous Velocity or Chance layer, including values, shading, roll divisions, and cycle marks; selection outlines remain visible. The modifier covers grid selection and selected-value drags, channel solo, and pattern copy-source selection. Undo/redo use the physical Command/Shift keys independently of Select. It preserves the Velocity/Chance layer and is cleared by Escape or editor focus loss. This state is never persisted or published to audio processing.

Velocity and Chance are explicit choices: clicking either selects that layer and clears latched Select. The three segments share one active-state update, with orange reserved for the active segment. The active segment paints above its neighbors so its shared border remains complete; there is no focus underline.

With no cells selected, Option temporarily shows Chance. With a selection, Option preserves the current layer and arms duplication: the grid uses a copy cursor, the compact Copy button lights, and dragging duplicates the selected cells without changing their values. Releasing Option returns to the latched Copy setting. An Option-click without a drag leaves the selected cells intact.

The string command adapter is retained solely for the existing command-contract tests and compatibility with internal callers. It has no web transport, resources or browser objects.

The header shows a read-only project name with a circled-info button inside it. Project details opens in a native overlay with explicit Apply/Cancel, editable name, author and description, and read-only Created and Last modified labels. Metadata drafts never write on focus loss and are discarded when a replacement document arrives. `projectAuthor` is persisted alongside the existing project metadata in host and project-file state; older projects default to an empty author. Created is preserved when details are edited; Last modified updates automatically on Apply and save.

Save updates the current file directly; the first save opens the filename dialog. Save As in Project details applies the draft and opens a file dialog for a copy. The processor retains the save destination for the current session, so reopening the editor does not forget it. New projects and host-state replacements clear that association. File paths are never serialized into projects or host state. Save As preserves the created date and author; a replacement document cancels an outstanding save dialog before it can write the wrong state.
