# Native editor and engine contract

The C++ engine is authoritative. `PluginProcessor::nativeUiState()` copies an immutable playback snapshot, refresh length, revision and document epoch under the engine mutex. No painting calls the engine or builds JSON.

`KshUiBridge` is a message-thread notification boundary. Engine callbacks increment its revision; they never call an editor while the engine mutex is held. The processor alone drains the audio hit FIFO and delivers typed `NativeHit` notifications. The native controller registers for its lifetime and removes its callback on destruction. Audio processing remains snapshot-only and lock-free.

The visible editor polls at 60 Hz. Only changed state or flash/playhead regions repaint. Pending cell edits carry their original expected values and document epoch. `applyNativeCellEdits` validates the entire batch before applying it and publishes one coherent snapshot. Recording wins conflicts; replacement documents cancel drafts and clear history.

The audio callback only enqueues hit notifications and sets work flags. The processor drains them on its 120 Hz message-thread timer, including with the editor closed. The visible editor also asks the processor to drain hits immediately before its playback repaint pass. Audio processing never calls `triggerAsyncUpdate()` to wake the UI.

Pattern recording uses separate bounded queues for incoming MIDI (audio-thread producer) and pad/QWERTY input (message-thread producer). The message thread drains both queues under the engine mutex; no SPSC queue has multiple producers.

The superscript padlock beside Record controls capture quantization: closed uses full grid snap, open retains early/late timing in the existing integer-percent cell nudge. Right-click (or Shift-F10 while focused) offers 0/25/50/75/100% strength and a signed recording offset from -100 to +100 ms. Partial strength reduces the captured residual toward the swung grid; 100% preserves the existing nearest-step behavior. The offset adjusts placement, never audition latency. Changes apply to future hits without rewriting existing cells. Processor-owned `patternRecordQuantizeStrength` and `patternRecordOffsetMs` are optional, strictly validated `v:1` project/host fields; older saves default to 100% and 0 ms, and New resets them. Cell undo does not change capture settings.

MIDI and UI capture share `KshPatternRecording` geometry, using the armed pattern's rate and per-channel loop/direction. Unlocked capture measures the residual from the deterministic swung onset, avoiding double-applied swing. The recorded nudge travels with the queued hit, preserving capture decisions when the UI is busy or quantization changes before a drain. One hit per cell remains the limit, with later hits overwriting its velocity and nudge. Integer-percent rounding is intentional; this is feel-preserving recording rather than sample-accurate event storage.

The audio thread publishes a coherent PPQ/BPM/wall-clock/loop/document-epoch anchor through its own preallocated mailbox. UI triggers use that anchor with a 250 ms freshness limit. The standalone holder excludes its own virtual-output source before forwarding external MIDI unchanged to JUCE's player and also captures original driver timestamps into a bounded recording queue. Driver producers are serialized by a mutex that the audio thread never acquires. The audio thread maps those timestamps through a fixed history of the same transport anchors, bypassing JUCE's previous-interval-to-next-block remapping for recording placement only. Plugin MIDI continues to use host-provided sample offsets. Calculations use the rate supplied to `prepareToPlay`. Mobile input discovery uses MIDI-device-change notifications to auto-open new external inputs, preserving subsequent manual choices. KSH Output is always excluded, by endpoint identifier and output name, and cannot remain enabled through saved settings or a manual enable. The incoming-message callback also rejects it before forwarding or recording, closing the interval before a device-manager change notification is handled. This prevents generated MIDI from being echoed through the standalone processor indefinitely.

Standalone MIDI routing defaults to the local `KSH Output` source. An explicit AudioDeviceManager output selection takes priority, including Network MIDI, USB and app destinations. The native editor exposes this through MIDI Out in the full-layout footer and Settings / View / MIDI Output in compact mode; AUv3 does not expose standalone routing. The wrapper supplies message-thread menu/name callbacks, reinstalls them on processor reset and clears them on teardown. Route changes detach the player, clear queued messages and send all-notes-off to the old destination before switching, then start timestamped output and save device settings. The iOS app enables the shared CoreMIDI network session before JUCE initializes endpoint discovery. On iOS 18 and later JUCE treats the session's port as a multi-group UMP device and gives it no MIDI 1.0 identifier, so `MidiOutput` cannot list or open it. The picker therefore offers Network Session as a native route: the player keeps sending to `KSH Output` and `StandaloneNetworkMidiForwarder` relays that source's timestamped event lists to the session's destination. Leaving the route sends all-notes-off to the session. The choice is saved as `kshNetworkMidiOutput` in standalone settings and retried on MIDI device changes until the port exists. A JUCE-listed copy of the session, if any, is hidden. The iOS Info.plist describes local-network access.

iOS builds default to `KSH_IOS_ICLOUD_ENABLED=OFF` for Personal Team signing. App and AUv3 use generated entitlements without iCloud/ubiquity keys and omit the ubiquitous-container Info.plist declaration. The project library starts in local Documents/KSH and does not observe iCloud-account changes or start cloud discovery in this mode. File-picker access, coordinated reads/writes, saved bookmarks, sharing and project-conflict checks remain available. Enabling the CMake option restores the fixed shared container and requires the corresponding paid-team capabilities.

On iOS, numbered row pads sit to the left of the channel names in both compact iPhone and full iPad layouts. They use native button press callbacks (`setTriggeredOnMouseDown`) and call `triggerRowFromUi` directly, with the same fixed velocity 100 as QWERTY. This handler queues the MIDI audition and, when armed with a fresh playing transport anchor, the recording event through the existing bounded queues without engine mutation or the engine mutex. The audio thread owns MIDI emission and note-off deadlines; the processor drains recording writes on the message thread. Pads do not toggle, auto-repeat, clear cell selection or borrow the Select modifier. Independent row buttons allow concurrent presses; their identity follows the channel through visual row reversal. Their local hit flash is painted and expired on the message thread.

QWERTY auditions retain their handler timestamp and are phased within the next processing block, using a consistent nominal one-block scheduling delay instead of snapping every audition to sample zero. Engine-generated auditions retain their existing explicit delay behavior. Recording monitor deadlines suppress the same cell's sequencer attack for that captured occurrence, including deferred early hits; subsequent loop passes play normally. Audio-side suppression storage is fixed-size and never enters project persistence. OS key delivery and external MIDI/audio routing latency remain outside this internal timing guarantee.

Each armed recording pass is one editor undo action, spanning all loop iterations until Record is turned off. The processor journals only recorded cell writes on the message thread, coalescing repeated hits per cell; the controller consumes these changes separately from manual gestures. Undo restores the pre-recording values of overwritten cells and removes new hits while preserving unrelated edits through the usual conditional field merge. Undo while still armed closes the recorded portion so subsequent hits start a new undo action. Disarming drains queued hits; session tokens discard late hits from stopped passes. Project replacement disarms recording, clears the journal and invalidates its history along with other editor history. No history work or allocation occurs on the audio thread.

`RealtimeMailbox` coalesces unconsumed updates through one lock-free atomic pointer. A new publication replaces and recycles the previous pending snapshot, while the consumer's current snapshot remains immutable. Retired slots are recycled on the producer side; all producer operations are serialized by the engine mutex. Bursts while audio processing is suspended still deliver the latest state on the next callback.

Deferred MIDI note-ons and note-offs use absolute deadlines on a monotonic callback sample timeline. Block sizes can change without shifting an event's deadline. Playback reset clears the pending events and sample timeline together.

Cells carry an integer `nudge` from -100 to +100 percent of one step (zero is on the beat). It shifts the entire hit, including its roll repeats, before/after the normal swing and humanize timing. Timing humanize independently shifts each hit, including every roll repeat, uniformly before or after its swung position; at 100% the range is ±20% of one step. Negative offsets are preserved. When nudges or humanize can produce early hits, the runner evaluates enough steps ahead to cover their combined range and queues later hits on the same absolute sample timeline; the visible playhead still follows the host. Host loop-start hits are anticipated before the wrap. Starting playback or seeking cannot emit into the past, so an early hit at the landing step is clamped to the first sample. Stop and seek cancellation also discard anticipated notes. MIDI export bounds lookahead to one pattern pass.

The inspector's Nudge control replaces the selected-cell count. It applies a common delta to all enabled selected cells, anchored to the first selected cell's displayed percentage. Mixed values show a dash. The delta stops when any selected cell reaches -100% or +100%, preserving the group's timing differences. A gesture is one undo action; cancel and conditional history include the nudge field. Grid slots stay on the beat while enabled shapes, their selection outlines, accessible bounds and hit tests move horizontally by `nudge / 100 * cellWidth` in both layouts and layers.

The grid always includes deterministic swing in those positions, using playback's shared `swingDelayStepsForPosition` calculation. The filled cell starts at its first swung hit plus nudge; roll shading and onset ticks use each repeat's own calculated swing phase, including ticks beyond the cell body. Straight beat slots stay fixed. Swing/subdivision automation updates both paint and accessible bounds immediately. For channel loops and reverse/ping-pong modes, the display uses the cell's next visit in the playback order, refreshing its phase from an audio-thread atomic global-step counter. When stopped it previews the first visit. No timing values are written back to cells, and random humanize is not baked into this deterministic display.

Nudge persists in strict `v:1` projects through optional sparse `cellNudges` rows `[source, channel, step, percent]`, including disabled and hidden cells. The existing `cells` rows keep their nine-field layout, so historical ten-field cycle-offset rows remain unambiguous. Missing nudge data defaults to zero. Typed snapshots, copy/move, generated cells and JSON cell inspection all retain the field.

Transport discontinuities never leave notes hanging. Stop, device off, seeks, bypass and state restores send note-offs for every sounding note at sample 0 and drop queued note-ons. After a jump, a step whose start falls at the landing position plays; a mid-step landing waits for the next boundary. When the host reports a loop, steps at or after the loop end are left for the next pass. A wrap to the loop start keeps pending notes and cycle phases, and plays the loop-start step even if the host did not split the block there. Cycle phases restart per cell, only when that cell's cycle length or mask changes.

Generative modes pick sources on the audio thread at each refresh boundary with a fixed-seed RNG, so the step that opens a window plays the new choice and offline renders repeat. The runner reports its choices through a FIFO; the engine mirrors them for the preview only when they extend its current `generationVersion`. Deliberate recompositions (mode, lock or channel changes, reset) bump that version, and the runner adopts the engine's choices. Undo and redo keep the current generated sources rather than re-rolling them.

Discrete commands go directly to `dispatchUiEngineCommand`, without JavaScript or serialized command messages. Convert native zero-based indices to the engine's one-based command indices once at this boundary. Numeric APVTS gestures pair begin/end callbacks. Row audition calls `triggerRowFromUi` directly through the existing realtime queue.

History groups a gesture into one action and conditionally merges only its changed fields. External changes are rebased out of active transactions; undo/cancel preserve unrelated recording and automation. Histories are capped at 128 entries. History stores typed document settings plus only the cells a gesture changed; JSON is used only to apply an undo through the persistence validator. A scroll-wheel adjustment is one action and one host gesture, closed after 350 ms without ticks or as soon as another edit begins. Text fields retain their native text undo. Project loads use the existing strict v:1 persistence validator and atomic file replacement.

`KshLayout` supplies cell bounds and hit tests. The grid and generated preview remain together in one native editor. Adjustable scale is 50–400%, with 100% equal to 85% of the design geometry (approximately 1137 × 782 points for the eight-channel desktop standalone). Standalone saves the zoom locally, including its reference size so older settings migrate once without shrinking the current window. Zoom and old theme metadata are not written into projects or host state; rendering uses the fixed Alternative palette.

iOS standalone uses automatic viewport fitting instead of the saved zoom. Landscape viewports up to 1100 × 500 points use a compact layout with eight channel rows, manual 16-step pages, an always-visible inspector and auxiliary control pages; see [iphone-release.md](iphone-release.md). Compact geometry and gesture modes are editor-local and never persisted. Wide viewports retain the original layout. The fullscreen wrapper owns editor bounds, with no fixed aspect ratio or minimum zoom constraint. The selected native layout is scaled uniformly and centred inside the available safe area on every resize or preferred-layout change. The scale control displays a read-only `Fit`; fitting does not overwrite project zoom metadata. Desktop standalone and hosted plugins retain their adjustable scale.

The desktop footer displays control help directly from each hovered control's `TooltipClient`, walking up from nested children when necessary. It replaces the old source/channel status line, is blank off controls, and wraps long tips across two lines without shrinking the font. There is no floating tooltip window. The footer `Tips` toggle beside `DC` enables this help and defaults on, independently of the retired floating-tooltip preference. Its `footerTooltips` preference is saved locally (`ofsound/KSH.ui.settings` in Application Support on Apple platforms), independently of project and host state. Compact layouts retain their existing geometry and tooltip strings.

The row-order icon between `Tips` and `DC` reverses vertical channel presentation: channel 1/red moves to the bottom and channel 8 to the top. `Layout` maps visual rows to the original channel indices for painting, hit tests, row controls, loop handles, keyboard navigation and drag targets. Generated previews follow the same order. The `reverseRows` preference is saved in the same local UI settings file; it never changes MIDI, cell data, project/host state, selection identity or undo history. Compact grids respect the preference while keeping their existing footer-free layout.

Select beside Velocity/Chance is an editor-local Shift modifier. Tap to latch or unlatch; holding for at least 300 ms, or using it for a modified action with another touch, is momentary. Physical Shift also lights Select, and releasing it preserves any latch. While active, cells retain the previous Velocity or Chance layer, including values, shading, roll divisions, and cycle marks; selection outlines remain visible. The modifier covers grid selection and selected-value drags, channel solo, and pattern copy-source selection. Undo/redo use the physical Command/Shift keys independently of Select. It preserves the Velocity/Chance layer and is cleared by Escape or editor focus loss. This state is never persisted or published to audio processing.

Velocity and Chance are explicit choices: clicking either selects that layer and clears latched Select. The three segments share one active-state update, with orange reserved for the active segment. Select stays highlighted whenever cells remain selected, including after releasing Shift or a momentary Select hold; the remembered Velocity/Chance layer still governs their values. Clearing the selection returns the highlight to that layer. This indicator does not latch the selection modifier or prevent moving selected cells. The active segment paints above its neighbors so its shared border remains complete; there is no focus underline.

With no cells selected, Option temporarily shows Chance. With a selection, Option preserves the current layer and arms duplication: the grid uses a copy cursor, the compact Copy button lights, and dragging duplicates the selected cells without changing their values. Releasing Option returns to the latched Copy setting. An Option-click without a drag leaves the selected cells intact.

The iPhone pattern picker is a separate child overlay, independent of the settings navigation and cell-selection modifier. Pattern taps select only. Its local duplicate source/destination do not arm the controller's copy state until the explicit confirmation; dismissal, viewport changes and document-epoch changes discard that draft. Settings pages remember their last tab, hide grid-only tools and the cell inspector, and keep undo/redo and standalone transport available. Channel settings is contextual to the row. Clear-pattern confirmation is tied to the source and document epoch so a changed document or source cannot inherit an earlier confirmation.

The string command adapter is retained solely for the existing command-contract tests and compatibility with internal callers. It has no web transport, resources or browser objects.

The header shows a read-only project name with a circled-info button inside it. Project details opens in a native overlay with explicit Apply/Cancel, editable name, author and description, and read-only Created and Last modified labels. Metadata drafts never write on focus loss and are discarded when a replacement document arrives. `projectAuthor` is persisted alongside the existing project metadata in host and project-file state; older projects default to an empty author. Created is preserved when details are edited; Last modified updates automatically on Apply and save.

Save updates the current file directly; the first save opens the filename dialog. Save As in Project details applies the draft and opens a file dialog for a copy. The processor retains the save destination for the current session, so reopening the editor does not forget it. New projects and host-state replacements clear that association. File paths are never serialized into projects or host state. Save As preserves the created date and author; a replacement document cancels an outstanding save dialog before it can write the wrong state.

Desktop pattern buttons 1–16 support native MIDI file dragging. Click selects and Shift-click chooses a copy source; drag at least six pixels to export the dragged pattern without selecting it or copying its cells. Drop onto a DAW MIDI track or clip slot. Each drag writes a unique, single-track Standard MIDI File (SMF0, 960 ticks per quarter note) named after the project and pattern. The file remains in the OS temporary directory after the drag so delayed host imports can finish.

Export renders one pass using that pattern's own length, rate and channel loops, plus direction, mutes, rolls, nudge, swing, probability and humanization. It starts cycle gates from their first visit and uses a fresh, repeatable random phase. Generative mode, the live playhead and device bypass do not change which numbered pattern is exported. Notes stop at the pattern boundary; the end marker preserves trailing silence. No tempo or meter events are written, so the destination DAW controls tempo. Rendering and file I/O stay on the message thread and never advance live playback or alter project/undo state. Native external file dragging is enabled on desktop only.

## Standalone Zen mode

The footer's Zen toggle is available in standalone only. Desktop Zen enters native OS fullscreen and hides the standalone title bar. The existing scale control changes only the centered interface inside the fullscreen viewport; unused space is black, and the interface is capped at the available screen size. Escape or Zen exits and restores the window chrome and location. On iPad standalone, Zen keeps the existing fullscreen viewport and enables manual centered scaling instead of automatic Fit. Hosted plugins do not expose Zen. Zen itself is transient and is not saved in project or host state.

The footer pie icon toggles graphical cell values. It hides velocity numbers while retaining the velocity fill and replaces probability percentages with a pie from empty (0%) to full (100%). Roll divisions, cycle marks, playback flashes, selection, and exact inspector/accessibility values remain available. The preference is saved locally as `graphicalCellValues` and is not part of project or host state.

Channel note fields open a modal piano chooser beside the field, including the compact channel settings field. The chooser provides octave buttons (C-1 through C9), a labeled one-octave piano, and explicit MIDI 0–127 entry using C4 = MIDI 60. Octave browsing is local; clicking a key or confirming a number commits one undoable channel-note edit and closes it. Escape or an outside click cancels. Dragging and scrolling note fields no longer retunes channels. The chooser closes on document replacement or external changes to its channel note and checks these again before assignment.

Inspector hover previews include Nudge, Roll and Cycle. These temporary, read-only grid overviews show signed timing offsets, repeat counts and cycle masks for enabled steps across every channel. Hovering works without a selection; editing remains selection-based in the inspector. Inspector gestures retain the matching overview until release/cancellation, then restore the chosen Velocity/Chance layer. Overview rendering anchors each value in its own step slot so shifted hits remain easy to compare.

Swing targets are multiples of the current step division: `1x` delays alternating steps, `2x` delays alternating two-step groups, and `4x` delays alternating four-step groups. At 100% swing, the delay is half the target group length. Playback, grid positions, MIDI export, and recording quantization share this timing calculation.

The desktop logo exposes two accent selectors: K selects orange and H selects blue. The choice is stored in local UI preferences (`blueAccent`), outside project and host state. A message-thread palette notification refreshes all open editors in the process, including cached label and LookAndFeel colors. Logo double-click still opens the auxiliary panel.

### iOS cloud project access

On iPhone/iPad, `IOSProjectLibrary` handles document pickers, sharing and file
access outside the processor. Both device families and AUv3 use
`iCloud.com.ofsound.ksh` as their default library, with local Documents/KSH as a
fallback. A metadata query discovers cloud placeholders; a serial background
queue downloads/coordinates reads and atomic writes. Saves compare the last
read/written content digest and unresolved file versions before replacing a
file. A conflict requires Save As or reopening the original.

The processor retains the library across editor recreation. Standalone-only
preferences retain the security-scoped bookmark and baseline digest. These are
never serialized in strict v:1 projects or host state. Native file callbacks
check the document epoch; loads additionally check the revision so intervening
edits/recording cannot be discarded. Saves serialize a snapshot before opening
the picker and mark the document clean only if its revision still matches.
Share exports that snapshot without changing the current save association.
